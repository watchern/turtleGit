# turtleGit — 复刻 TortoiseGit 体验的 VSCode 插件

> 阶段：分析 + 架构设计（未开工）
> 目标平台：**跨平台（Linux 原生支持是核心动机，TortoiseGit 不支持 Linux）；不调用 TortoiseGit 进程**
> 目标 VSCode：1.100+（当前稳定版约 **1.140**，实测 `@types/vscode@1.140.0`）
>
> 注：本文是立项时的分析快照。后续演进见文末「实施进度」，其中跨平台改造（2026-10-20）已移除 external 桥接档。

---

## 一、结论先行

1. **"弹窗"能用，但不是原生模态框。** 稳定 API 里没有 `ViewColumn.Modal`（已核对 `@types/vscode@1.140.0`，0 命中）；1.110 的 `extensions.allowOpenInModalEditor` 只对内置扩展/MCP 视图生效，不是给第三方扩展的通用 API。真正可用的"弹窗"是 **WebviewPanel + 浮动窗口（auxiliary window）**，或 **直调 TortoiseGitProc.exe**。
2. **数据层必须自己调 git CLI。** 内置 `vscode.git` API 只覆盖了约 60% 的 TortoiseGit 能力，缺交互式 rebase、stash 列表、reflog、submodule、bisect、按块暂存等。
3. **UI 层必须 webview。** TortoiseGit 的核心价值（变更树三态勾选、提交/日志双栏对话框、版本分支图）在 VSCode 原生控件里无法实现，webview 是唯一路径。
4. **建议做成"三档弹窗策略 + 一个内核"**，策略可配置、可运行期降级，避免押注单一不稳定 API。

## 二、VSCode 能力边界（实测核对）

### 2.1 弹窗/窗口：三条路

| 路径 | 机制 | 稳定度 | 体验 | 结论 |
|---|---|---|---|---|
| **A. 浮动窗口** | `createWebviewPanel()` 后执行 `workbench.action.moveEditorToNewWindow` | 稳定（1.86+ 命令，1.100+ 支持 compact/置顶） | ✅ 真·独立 OS 窗口，最像 TortoiseGit；可拖到副屏、可置顶 | **主推** |
| **B. 编辑器内标签页** | `createWebviewPanel(..., ViewColumn.Active/Beside)` | 最稳 | ⚠️ 是标签页不是弹窗，但零风险 | **保底** |
| **C. 外调 TortoiseGit** | spawn `TortoiseGitProc.exe /command:commit /path:"..." /closeonend:2` | 稳定（仅 Windows） | ✅ 原汁原味原生窗口、零 UI 成本；❌ 无法与 VSCode 状态深度联动 | **彩蛋/兼容模式** |
| ~~D. ViewColumn.Modal~~ | `ViewColumn.Modal = -4`（PR microsoft/vscode#307838） | ❌ 未进稳定 API | 理想形态（居中模态遮罩） | **写能力探测，未来自动启用** |

关键事实：
- `ViewColumn` 枚举稳定成员仍为 `Active=-1, Beside=-2, One..Nine`，**无 Modal**。
- 浮动窗口对 iframe 类编辑器（webview）的支持已打通（GitLens 图形视图已验证），**已知小坑：首次拖入可能出现"持续加载"，点一次刷新即恢复** → 我们做"自动 reload 一次 + 提供手动刷新按钮"兜底。

### 2.2 数据层：内置 Git API vs git CLI

内置 API（`vscode.git` 的 `getAPI(1)`）可提供：`status / diffWith(HEAD) / diffBetween / log / commit / add / revert / clean / checkout / createBranch / getBranches / getRefs / tag / merge / rebase / applyStash / blame / fetch / pull / push / getMergeBase / toGitUri` 等。

**缺**（TortoiseGit 用户日常必需）：交互式 rebase、stash 列表与详情、reflog、submodule 状态、LFS、bisect、按块/按行暂存、cleanup、revision graph 拓扑、repo-browser（树浏览）、patch 序列化、issue tracker 集成。

→ **决策：命令执行走 git CLI；状态订阅走内置 API 事件。**
- 执行：`child_process.spawn(git, [...])`，统一加 `-c core.quotepath=false -c i18n.logOutputEncoding=utf-8`，解析用 `-z` / `--porcelain=v2` / 自定义 `--pretty=format:%H%x1f...`，规避中文路径与分隔符转义。
- 状态：`vscode.git` 的 Repository 对象用于感知 HEAD/分支/变更，保证与内置 SCM 面板不打架、写完自动刷新。

### 2.3 其他可用 API（对应 TortoiseGit 习惯）

| TortoiseGit 习惯 | VSCode 落点 |
|---|---|
| 图标覆盖（icon overlay） | `window.registerFileDecorationProvider` → 资源管理器文件角标 M/A/D/! |
| 右键菜单（按状态动态显示） | `menus.explorer/context`、`editor/context`、`scm/resourceState/context` + `when` 上下文键 |
| 提交进度对话框 | `window.withProgress({ location: Notification })` |
| 差异对比 | 自带 diff webview（并排/统一）+ `vscode.diff` 打开原生 diff（`git:` scheme URI） |
| 外部对比/合并工具 | 配置项 + spawn（TortoiseGitMerge / Beyond Compare） |
| 设置对话框 | `contributes.configuration` |
| 状态栏分支信息 | `window.createStatusBarItem` |
| 快捷键（Ctrl+Enter 提交、Esc 关闭、F5 刷新） | `contributes.keybindings` + 面板内接管 |

## 三、TortoiseGit 交互习惯清单（复刻目标）

**核心对话框**
1. **Commit**：上半变更树（三态复选框、按状态着色、双击看 diff、右键 add/revert/ignore）、changelist 分组、部分文件提交（按块）、提交信息（模板/历史/拼写检查/bugID）、amend、进度对话框。
2. **Log**：上栏=提交图+列表（graph lane、作者、日期、信息、分支/标签徽标），下栏=该提交变更文件，右键=revert/reset/cherry-pick/建分支标签/与工作副本比较，顶部过滤（消息/作者/路径/正则/日期范围），统计页（作者直方图/日期图），All branches 开关、"显示整个项目 vs 当前路径"。
3. **Check for modifications**：按状态分组的变更列表（≈ VSCode SCM，但按目录树聚合 + 状态列）。
4. **Revision graph**：纯拓扑图（分支/合并/标签节点，右键操作）。
5. **Repo-browser**：任意版本的目录树 + 文件内容预览。
6. **Diff**：文件级/行级、并排与统一、忽略空白与行尾、图片 diff、外部工具。

**操作集**：add / ignore / delete / rename / revert / cleanup / reset / stash / bisect / branch / tag / merge / cherry-pick / rebase / resolve conflicts / create patch / apply patch / blame / export / reflog / submodule / LFS / issue tracker。

**肌肉记忆**：右键即达、双击看差异、Ctrl+Enter 提交、Esc 关闭、F5 刷新、路径范围可选（当前文件 vs 整个仓库）。

## 四、架构设计

### 4.1 分层

```
turtleGit/
├─ src/
│  ├─ extension.ts              激活入口：命令/菜单/视图/状态栏注册
│  ├─ host/                     【宿主层 Node 侧】
│  │  ├─ git/
│  │  │  ├─ GitRunner.ts        spawn 封装：进程池、超时、取消、编码、错误归一化
│  │  │  ├─ parsers/            status(v2 -z) / log / branch / stash / reflog / diff / graph
│  │  │  └─ commands/           status log commit stage unstage branch merge rebase stash …
│  │  ├─ core/
│  │  │  ├─ RepositoryStore.ts  仓库状态 + 缓存 + 变更事件（订阅 vscode.git 事件触发失效）
│  │  │  └─ FileStatusCache.ts  文件状态索引（供装饰器与视图查询）
│  │  ├─ ui/
│  │  │  ├─ PanelManager.ts     webview 生命周期：单例/reveal/浮窗切换/序列化恢复
│  │  │  ├─ FileDecoration.ts   图标覆盖
│  │  │  ├─ StatusTreeView.ts   "检查修改"树视图
│  │  │  └─ Progress.ts         进度对话框
│  │  ├─ tgitBridge/            可选：安装探测 + TortoiseGitProc.exe 调用（C 档策略）
│  │  └─ rpc/                   postMessage RPC 服务端（类型安全的 handler 注册）
│  ├─ webview/                  【UI 层 Browser 侧，Vite 构建】
│  │  ├─ apps/                  commit / log / graph / diff / stash / branch / settings
│  │  ├─ components/            CommitTree(三态) / LogTable / GraphCanvas / DiffViewer / SplitPane / Toolbar
│  │  └─ bridge/                RPC 客户端 + 主题变量同步
│  └─ shared/                   RPC 契约类型、状态枚举、i18n（中/英）
└─ docs/
```

### 4.2 关键设计决策

| 议题 | 决策 | 理由 |
|---|---|---|
| 依赖 | **不引 simple-git / isomorphic-git**，直调 git CLI | 与 TortoiseGit 同源（它也是 git.exe 封装），零依赖、能力完整、行为一致 |
| 弹窗形态 | `PanelMode = auto \| floating \| embedded \| external`，配置化 + 运行期降级 | 不押注单一 API；`auto` 按 `ViewColumn.Modal → floating → embedded` 探测 |
| 通信 | 类型安全 RPC（请求/响应/事件三元组），共享 `shared/rpc.ts` | 避免 postMessage 字符串地狱，UI 与宿主解耦 |
| Diff 呈现 | **双轨**：双击默认开 VSCode 原生 diff（免费语法高亮/导航）；插件内提供 TortoiseGit 风格并排 webview | 兼顾效率与复刻度 |
| 版本图 | `git log --topo-order --parents --pretty` + 自研 lane 分配算法，Canvas/SVG 渲染 | 内置 API 无拓扑数据，必须自算 |
| 部分提交 | `git diff -U0` 生成 hunk → 勾选 → `git apply --cached --recount` | 复刻"只提交文件的一部分" |
| 凭据 | 不自建；push/pull 走系统 credential helper，交互型操作优先用 terminal 或内置 API | 避免 TTY 挂起与凭据泄露 |
| 性能 | log 分页 + 增量 `--skip`、状态缓存、图虚拟化渲染 | 大仓库（>10 万提交）可用 |
| 状态一致性 | 写操作后主动触发内置 git 扩展刷新 | 避免 VSCode SCM 面板与插件视图不一致 |

### 4.3 弹窗策略实现要点（`PanelManager`）

```ts
type PanelMode = 'auto' | 'floating' | 'embedded' | 'external';

// 1) 建 panel（永远先 embedded，保证可用）
const panel = vscode.window.createWebviewPanel('turtleGit.commit', title, vscode.ViewColumn.Active, opts);
// 2) 能力探测：优先 Modal（未来），其次浮动窗口
if ((vscode.ViewColumn as any).Modal !== undefined) { /* 未来：直接用 Modal */ }
else if (mode === 'floating') {
  await panel.reveal();                       // 必须先成为活动编辑器
  await vscode.commands.executeCommand('workbench.action.moveEditorToNewWindow');
  // 兜底：首帧空白已知问题 → 注入 reload 逻辑
}
// 3) external（Windows）：spawn TortoiseGitProc.exe /command:commit /path:... /closeonend:2
```

风险与对策：
- **浮动窗口首帧空白** → 面板内 `onDidChangeViewState` 首次激活时 `panel.webview.html = html` 重设一次 + 工具栏刷新按钮。
- **`moveEditorToNewWindow` 有副作用**（把编辑器移出主窗口）→ 用后提供"收回主窗口"命令；`copyEditorToNewWindow` 可作为不移动原编辑器的替代（待实测取舍）。
- **web/远程场景**（vscode.dev、SSH）无 OS 窗口 → 自动降级 embedded。

## 附：跨平台改造（2026-10-20，需求变更）

动机：TortoiseGit 不支持 Linux，用户要在 Linux 上保留 TortoiseGit 使用习惯，且**明确要求不调用 TortoiseGitProc.exe**。

- **移除 external 桥接档**：`PanelMode` 收敛为 `auto | floating | embedded`；删除 `turtlegit.tortoiseCommit` / `turtlegit.tortoiseLog` 命令、`tryExternal`、`findTortoiseGitProc` 及 package.json 相关声明。
- **新增 `src/host/core/paths.ts`**：统一跨平台路径规范（仓库相对路径恒为正斜杠；绝对路径用平台原生分隔符），替换原先散落各处的 Windows 硬编码（`RepositoryStore.repoForPath`、`parsers.joinRepo`、`GitService.repoRootOf/repoName`、`FileDecorationProvider`、`StatusTreeProvider`、`PanelManager.relPath/gitRevUri` 等）。
- **GitRunner**：TortoiseGit 安装目录仅作为 Windows 上 git.exe 的探测来源（不调用 GUI 进程）；Linux/macOS 直接用 PATH 中的 git。
- **浮窗策略**：`moveEditorToNewWindow` 为跨平台命令，Linux 同样可获得独立窗口体验。
- 冒烟测试新增 `paths.ts` 平台无关断言（往返转换、仓库外路径返回 undefined）。
